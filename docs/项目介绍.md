# SpatialMem 项目介绍

## 1. 项目目标

SpatialMem 是面向多视角室内空间推理的工具型 Agent。系统由视觉语言模型规划任务，再调用 DA3、SAM3 和确定性几何工具完成物体计数、距离估计、方向判断、尺寸估计、出现顺序和路径规划。

系统在训练阶段积累两类跨样本知识：

- **Memory**：物体尺寸、场景尺度和未解决案例等事实性知识。
- **Skill**：可复用的工具调用流程、适用条件、检查规则和失败经验。

## 2. 总体架构

```text
SpatialSample
     |
     v
Orchestrator
     |
     +--> Memory 检索
     +--> SkillLib 检索
     |
     v
Planner
     |
     +--> 选择 Skill --> Skill.execute.py --------+
     |                                            |
     +--> 不选 Skill --> Reasoner/Raw-tool loop --+
                                                  |
                                                  v
                                         Ordered Context
                                                  |
                                                  v
                                      Reflector.finalize
                                                  |
                                                  v
                                            AgentResult
```

| 组件 | 职责 |
|---|---|
| `Orchestrator` | 负责单个样本的完整生命周期：准备输入帧、初始化运行状态、检索 Memory 和 Skill，并协调 Planner、工具调用、Checker 与 Reflector，负责控制各模块的执行顺序并汇总最终结果。 |
| `Planner` | 由 VLM 承担，负责理解用户问题和场景内容，分析任务类型，从候选 Skill 和底层工具中选择合适的处理路径，并生成工具调用计划和参数。 |
| `Reasoner` | 由 VLM 承担，负责在 Raw-tool 路径中读取当前上下文和已有工具结果，判断证据缺口，逐轮选择下一项工具及其参数，直到获得足够证据或达到调用上限。 |
| `Checker` | 由 VLM 承担，负责根据目标描述、图像证据、二维框和 3D 几何关系检查目标定位是否正确，修正错误实例或选定目标实例。 |
| `Reflector` | 由 VLM 承担，负责汇总工具输出和视觉证据，检查结果是否符合问题要求，判断是否需要继续调用工具，并在证据充分后组织最终答案。 |
| `ToolRegistry` | 统一注册和调用 DA3、SAM3、BEV、NVS 以及代码执行工具，负责参数传递、运行状态管理、错误处理和结果记录。它为 Skill 和 Raw-tool 提供一致的工具接口。 |
| `SkillLib` | 负责 Skill 的检索、加载、执行和效果统计，根据当前任务为 Planner 提供可复用的工具流程。训练过程中还负责维护 Skill 的暂存、晋升和失效隔离状态。 |
| `Memory` | 负责存储和检索物体尺寸、场景尺度、历史结论及失败案例等可复用知识，为 Planner 和 VLM 的当前决策提供先验信息。 |
| `TrainLoop / evolve.py` | 负责组织训练、评测和轨迹分析，根据运行结果更新 Memory，并生成、修正、筛选和晋升 Skill。它主要改进后续任务可使用的知识和流程，不参与单个样本的即时决策。 |

### Checker 组件详细介绍

### 1. 计数任务 Checker

插入在计数工具中。通过 DA3/SAM3、跨帧跟踪和 3D 聚类生成实例候选之后，将候选标注、出现帧和 3D 信息交给 Checker。VLM 检查完整帧序列，输出以下纠错操作：

- `missed`：补充完全漏检的目标；
- `spurious`：删除明确的非目标候选；
- `merge`：合并属于同一物体的重复候选；
- `split`：将包含多个物体的候选拆分为不同目标。

代码会校验实例编号和帧范围，确保没有虚构、重复或遗漏帧。校验通过后，执行对应修改并重新计算计数。

### 2. 其他任务的目标选择 Checker

插入在需要指定目标实例的任务工具中，如距离、方向、尺寸等。任务工具生成 SAM3 候选后，将候选标注、出现帧和 3D 信息交给 Checker 选择正确候选；如果没有可靠轨迹，也可以直接从原始帧中定位目标。

选定目标后，将实例 3D 信息交给代码工具计算具体的距离、方向、尺寸等。



## 3. 单样本推理流程

### 3.1 输入准备

数据加载器将不同数据集统一转换为 `SpatialSample`，其中包含问题、答案、图片路径、任务类型、答案格式、标注和原始字段。

`Orchestrator._prepare_run()` 会：

1. 清空上一个样本的工具上下文。
2. 创建当前进程的输出目录。
3. 将输入均匀限制到 `MAX_FRAMES_PER_SAMPLE=32`。
4. 保存问题、任务类型、帧路径和标注等运行状态。

### 3.2 Planner

Planner 同时读取：

- 问题和输入帧预览；
- 当前任务相关的 Memory；
- SkillLib 检索出的最多 3 个候选 Skill；
- ToolRegistry 的工具说明。

Planner 输出场景类型、`chosen_skill`、`skill_params` 和原始工具计划。`chosen_skill` 只能是候选 Skill 的名称或 `null`，不能填写底层工具名。

### 3.3 Skill 路径

Planner 选中 Skill 后，SkillLib 调用对应目录的 `execute.py`。Skill 内部仍通过 ToolRegistry 调用底层工具，因此结果进入统一上下文。

在评估和 Notebook 模式中：

- Skill 失败时可以回退到原始工具循环；
- Skill 成功后仍由 Reflector 检查证据；
- 证据不足时可继续追加工具调用。

训练模式可以关闭 Skill 后补救，以保留干净的失败轨迹供进化阶段分析。

### 3.4 Raw-tool 路径

没有合适 Skill 时，系统进入最多 3 轮的原始工具循环：

1. Reasoner 根据计划和当前证据选择下一步。
2. ToolRegistry 执行工具并记录结果。
3. 一轮结束后，Reflector 判断证据是否充分。
4. Reflector 选择终止或置信度达到 0.8 时结束。
5. 否则根据 `next_actions` 生成下一轮计划。

### 3.5 有序证据上下文

系统使用 `ordered_context` 按实际发生顺序追加记录，不会用新结果覆盖旧结果：

```text
Round 1: selected skill[count_objects]
[depth_estimation] ...
[object_segmentation] ...
[instance_3d_localization] ...
[checker] ...
[final_localization] ...
[reflector] confidence=..., decision=...
```

工具成功、失败、重复调用、Checker 结果和 Reflector 判断都会保留。Finalizer 最终读取这段文本，并结合原始帧、标注帧、BEV 和 NVS 等已有视觉证据生成答案。

## 4. 工具层

### 4.1 视觉感知工具

| 工具 | 作用 |
|---|---|
| `depth_estimation` | DA3 深度、置信度、相机内外参和处理后图像 |
| `object_segmentation` | SAM3 文本分割、检测框、置信度和视频 track |
| `annotation_localization` | 将数据集自带点或框转换为统一检测格式 |
| `bev_generation` | 根据 DA3 点云生成鸟瞰图 |
| `novel_view_synthesis` | 根据 DA3 3DGS 渲染新视角 |

### 4.2 几何与任务计算

| 工具 | 作用 |
|---|---|
| `instance_3d_localization` | 将 2D mask/box 反投影到 3D，并跨帧聚合实例 |
| `instance_counting` | 根据最终 3D 实例计算数量 |
| `distance_computation` | 计算物体间或物体到相机的距离 |
| `direction_computation` | 计算指定观察坐标系下的相对方向 |
| `object_size_computation` | 估计物体三维尺寸 |
| `scene_size_computation` | 估计房间范围和面积 |
| 任务专用计算 | 支持出现顺序、路径规划等后处理 |

### 4.3 3D 实例聚合

当前聚合分两阶段：

1. 相同 SAM3 video `obj_id` 的跨帧检测先归为同一候选实例。
2. 对剩余候选执行凝聚式 3D 合并。

第二阶段只有标签相同且从未在同一帧共现的候选才可合并。满足以下任一条件即可合并：

```text
3D IoU >= 0.20
3D IoS >= 按物体尺寸变化的 0.20～0.45
中心距离 <= 0.40 × 较小包围盒对角线
```

每轮选择满足条件且中心距离最近的一对，更新联合包围盒后继续比较，直到没有可合并候选。

## 5. Memory 与 Skill

### 5.1 Memory

Memory 保存物体尺寸统计、场景尺度统计和未解决案例。数值先验使用在线统计更新；新类别先进入候选区，达到 `WARMUP_N=5` 次观测后再进入稳定先验，减少异常值污染。

### 5.2 Skill

每个 Skill 是一个可执行目录：

```text
skill_name/
├── SKILL.md
├── execute.py
└── trajectories.jsonl
```

- `SKILL.md`：适用场景、参数、步骤、Checker 规则和失败经验。
- `execute.py`：参数化工具流程。
- `trajectories.jsonl`：压缩的历史轨迹，用于后续蒸馏。

新生成的 Skill 先进入 `pending/`，成功复用达到阈值后才晋升到主库。

## 6. 训练时自进化

`TrainLoop` 执行样本并与 GT 比较，`evolve_after_sample()` 再根据“是否正确”和“是否使用 Skill”选择更新路径：

| 路径 | 结果 | 使用 Skill | 动作 |
|---|---|---|---|
| A | 正确 | 是 | 记录成功轨迹并强化已有 Skill |
| B | 正确 | 否 | 将原始工具轨迹蒸馏为 pending Skill |
| C | 错误 | 是 | 反思并生成修正计划；重跑验证通过后更新 Skill 失败经验 |
| D | 错误 | 否 | 反思并重跑；验证通过后生成 pending Skill |

修正计划未通过验证时，只记录为未解决案例，不修改 Skill。

对于长期没有 Skill 覆盖的类别，系统会积累原始工具轨迹。当达到 `BOOTSTRAP_TRIGGER_N=8` 个样本且仍无候选 Skill 时，系统基于成功与失败轨迹主动生成 pending Skill。

评估阶段设置 `evolve=False`，只使用已有知识，不更新 Memory 和 Skill。

## 8. 训练与评测脚本

项目根目录中的主要入口脚本如下：

| 脚本 | 用途 |
|---|---|
| `train_vsitrain10k.py` | 在 VSI-Train-10k 上运行自进化训练；支持按任务类型选择、断点续跑、指定 GPU 和 checkpoint |
| `train_route_planning94.py` | 从 VSIBench 的 194 个路径规划样本中按固定随机种子划分 94 个训练样本和 holdout，并保存划分结果 |
| `train_spar.py` | 在 SPAR/ScanNet 的特有空间任务上训练；支持点和框标注渲染、按任务保存结果与断点续跑 |
| `eval_vsibench.py` | 使用完整 SpatialMem Agent 在官方 `test.jsonl` 上评测；评测时冻结 Memory 和 Skill，不执行 GT 驱动的反思重构或知识进化 |
| `eval_vsibench_qwen_baseline.py` | 将 RGB 帧和问题直接发送给 Qwen3-VL，不调用 SpatialMem 工具、Skill、Checker 或 Memory，用作直接 VLM 基线 |

`eval_vsibench.py` 对数值题使用官方 MRA，对选择题使用选项字母准确率。它支持按任务类型或样本数评测、选择 GPU、指定 checkpoint，以及配置 OpenAI 兼容模型服务。

训练脚本将结果按任务类型写入 `results/`，并持续更新指定 checkpoint 中的 Memory、主 Skill 库和 pending Skill。评测脚本只读取这些知识，不使用测试集更新它们。

## 10. 三种运行模式

**完整推理**

```text
SpatialSample -> Planner -> Skill 或 Raw-tool loop
              -> Reflector.finalize -> AgentResult
```

**训练**

```text
完整推理 -> 与 GT 比较 -> evolve_after_sample
         -> 更新 Memory / Skill / pending
```

**独立工具测试**

`SpatialMem.ipynb` 同时承担交互式演示和工具测试：

- 分任务随机加载 VSIBench 样本，覆盖计数、距离、方向、尺寸、出现顺序和路径规划；
- 对各类任务运行完整 Agent，查看 Planner、Skill/Raw-tool、工具证据和最终答案；
- 独立测试 DA3 深度、相机参数和点云；
- 对某一样本 32 帧图生成并展示 BEV 和 NVS；
- 对同一个计数样本切换32、 64 或 128 帧直接运行计数工具对比效果。



## 11. 关键默认参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `MAX_FRAMES_PER_SAMPLE` | 32 | 完整 Agent 每个样本最多使用的帧数 |
| `MAX_ROUNDS` | 3 | 原始工具循环最大轮数 |
| `CONFIDENCE_THRESHOLD` | 0.8 | Reflector 提前终止阈值 |
| `WARMUP_N` | 5 | Memory 候选先验晋升所需观测数 |
| `DISTILL_TRIGGER_N` | 5 | 已有 Skill 成功蒸馏触发间隔 |
| `DISTILL_WINDOW` | 20 | Skill 蒸馏读取的近期轨迹数 |
| `PENDING_PROMOTE_K` | 3 | pending Skill 晋升所需成功次数 |
| `BOOTSTRAP_TRIGGER_N` | 8 | 无覆盖类别主动生成 Skill 的轨迹数 |
| `REFLECT_MAX_ATTEMPTS` | 1 | 错误样本修正计划验证次数 |

一句话概括：

> SpatialMem 用 Planner 选择可执行 Skill 或动态工具链，用有序上下文和 Reflector 管理证据，再根据训练结果持续更新事实性 Memory 和过程性 Skill。
